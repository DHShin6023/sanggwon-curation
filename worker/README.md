# sanggwon-proxy

**카카오 REST 키를 숨기기 위해서만 존재하는 얇은 프록시.** 판정 로직은 여기 없다 —
등급·근거·대안·해설은 전부 `web/js/`가 만든다. 이 워커가 죽으면 주소를 좌표로
바꿀 수 없어 판정 자체가 안 되지만, 그 외에는 아무것도 여기 의존하지 않는다.

## 엔드포인트

| 경로 | 메서드 | 입력 | 출력 |
|---|---|---|---|
| `/geocode` | GET | `?q=주소` | `{lng, lat, gu_code, dong_code, address}` / 404 |

`gu_code`(5자리)·`dong_code`(8자리)는 **행정동 코드**(ADSTRD_CD)다. 카카오
주소검색의 `b_code`는 법정동이라 쓰면 안 된다 — `web/data/dong/*.json`의 키와
코드 체계가 달라 🟡 행정동 폴백이 통째로 죽는다. 자세한 건 `src/index.js`의
지오코딩 절 주석 참고.

## ⚠️ 2026-08-09: AI 엔드포인트 두 개를 걷어냈다

예전에는 `/narrate`(AI 해설)와 `/map-industry`(자유 입력 → 표준 업종)가 있었다.
둘 다 삭제했다.

**AI 해설을 없앤 이유.** 서비스 포지션이 정리되면서다. 이 서비스는 성패를 가르는
나침반이 아니라 **「자리와 업종의 궁합을 개략적으로 알려주는 조언자」**다(신동환).
그 정도 피드백은 `web/js/narrate.js`의 템플릿이 이미 데이터에서 만들어낸다 —
등급과 그 의미, 어느 축이 강하고 약한지 실제 수치로, 층수 계수가 얼마나 깎았는지,
함정상권 같은 패턴 경고까지. AI가 하던 일은 그걸 매끄러운 산문으로 엮는 것뿐이었고,
대가는 호출당 크레딧 + 결과 화면 최대 4초 지연이었다.

딸려서 사라진 것이 더 크다. `validateNarration`은 **오직 생성모델이 지어낼 수
있기 때문에** 존재하던 방어선이다. 이 프로젝트가 가장 많은 힘을 쏟은 곳인데,
모델을 빼니 그 위험 자체가 없어졌다. 템플릿은 거짓말을 못 한다.

**업종 매핑을 없앤 이유.** AI가 아니라 **사전**으로 푸는 문제였기 때문이다.
근거는 실측이다 — 창업자가 쓸 법한 어휘 37개를 넣어보니 이름 부분일치만으로는
26개(70%)가 실패했고, 그것도 카페·치킨집·술집·빵집·약국·병원처럼 가장 흔한
말들이었다("카페"는 "커피-음료"에 걸리지 않는다). 그래서 별칭 사전
`data/domain/industry_aliases.json`을 만들었고, 같은 37개가 **전부 통과**한다.

사전이 AI보다 나은 지점: 공짜고, 즉시고, 거짓말을 못 하고, 틀리면 한 줄 고치면
된다. (AI 매핑은 「미용」을 자동차미용으로 보내던 오답 전력이 있다.) 그리고
현장에서 사람들이 뭐라고 부르는지는 모델보다 신동환이 안다.

**함께 사라진 것:** OpenRouter 호출, KV 일 한도 카운터, 지출 상한, `spend()`,
모델 타임아웃, `MODEL` 설정, 그리고 **KV 바인딩 자체**.

되살릴 일이 생기면 git 이력에서 꺼내되, 클라이언트 쪽 `validateNarration`을
**반드시 함께** 되살릴 것. 검증 없이 모델 문장을 화면에 올리는 건 이 프로젝트에서
한 번도 허용된 적이 없다.

## 배포

```bash
npx wrangler login

# 키는 secret으로만 넣는다 (wrangler.toml·코드에 절대 넣지 않는다)
npx wrangler secret put KAKAO_REST_KEY

npx wrangler deploy
```

KV 네임스페이스는 더 이상 필요 없다. OpenRouter 계정·모델 id도 필요 없다.

배포 후 출력되는 `*.workers.dev` 주소를 `web/js/main.js`의 `PROXY` 상수에 넣는다.
그 전까지는 `<계정>` 리터럴이 박혀 있어 **지오코딩이 실패하고 화면에 「주소 조회에
실패했습니다」가 뜬다.** AI가 있던 시절과 달리 이건 조용한 폴백이 아니다 —
주소를 모르면 어느 상권인지 알 수 없고, 모르는 채로 등급을 지어낼 수는 없다.

## 남용 방지

`/geocode`는 **Origin 검사만** 걸려 있다. `ALLOWED_ORIGINS`에 없으면 403이고,
Origin 헤더가 없는 요청(curl 기본)도 403이다.

**이건 브라우저만 막는다.** `curl -H "Origin: https://dhshin6023.github.io"` 한 줄로
위조되므로, 작정한 상대에게는 카카오 할당량(10만/일)이 사실상 열려 있다.

제대로 된 해법은 Cloudflare가 무료로 주는 **Rate Limiting Rules**다.
대시보드 → Security → WAF → Rate limiting rules 에서:

- **매칭**: `URI Path equals /geocode`
- **기준**: IP당 `1분에 20건` 정도(정상 사용자는 주소 하나에 1건을 쓴다)
- **동작**: Block, 10분

콘솔에서 하는 배포 시점 결정이라 코드 범위 밖이다. **필수는 아니지만 공개 후에는
걸어두는 걸 권한다.** 카카오는 건당 과금이 아니라 무료 할당량이므로, 최악의 경우도
"청구서"가 아니라 "그날 지오코딩이 막힘"이다.

## 타임아웃

`fetch`에는 기본 타임아웃이 없다. 없으면 카카오가 멈출 때 "조용히 실패"가 아니라
**"조용히 멈춤"**이 된다 — 화면이 아무 변화 없이 서 있고 사용자는 뭐가 잘못됐는지
알 수 없다.

| 구간 | 한도 | 정의 위치 |
|---|---|---|
| 브라우저 → `/geocode` | 10초 | `web/js/main.js` `GEOCODE_TIMEOUT_MS` |
| 워커 → 카카오 (최대 3회) | 각 5초 | `src/index.js` `KAKAO_TIMEOUT_MS` |

워커 총 예산(최대 15초)이 브라우저 한도(10초)를 넘을 수 있는데, 그건 감수한다.
카카오는 건당 과금이 아니라 무료 할당량이라 버려지는 호출의 대가가 크레딧이
아니고, 사용자를 15초씩 세워두는 쪽이 더 비싸다. (AI가 있던 시절에는 반대 규칙이
필요했다 — 버려지는 호출이 곧 돈이었기 때문이다.)

## 테스트

```bash
node --test web/tests/worker.test.js
```

테스트 파일이 `web/tests/`에 있는 이유는 이 프로젝트의 공식 실행 명령이
`for f in web/tests/*.test.js; do node --test "$f"; done` 하나뿐이라서다.
다른 디렉터리에 두면 아무도 안 돌린다. 네트워크는 타지 않는다(카카오는 fetch 스텁).
