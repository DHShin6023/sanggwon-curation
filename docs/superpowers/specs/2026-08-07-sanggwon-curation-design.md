## 1. 한 줄 정의

**출점 예정지 주소·층수·오픈하려는 업종을 입력하면, 그 조합의 적합도를 4단계로 판정하고 근거를 설명하며, 그 자리에 더 맞는 대안 업종을 1안·2안으로 제시하는 웹서비스.**

---

## 2. 문제 정의

기존 상권분석 서비스(소상공인365, 서울시 우리마을가게, 나이스비즈맵, 오픈업 등)는
데이터를 **보여주는** 데 그치고 **해석은 사용자 몫**으로 남긴다.

```
유동인구  32,451명
점포수    12개
추정매출  4억 2,300만원
```

예비창업자는 이 숫자를 읽지 못한다. 알고 싶은 것은 **"그래서 하라는 겁니까 말라는 겁니까"**다.

동시에, 어떤 서비스도 **"그럼 여기엔 뭐가 맞습니까"**에 답하지 않는다.
"안 됩니다"에서 대화가 끊기고 사용자는 창을 닫는다.

---

## 3. 타겟 사용자

**일반 예비창업자.** 특정 물건지를 놓고 특정 업종 개업을 고민하는 개인.

경쟁이 가장 치열한 세그먼트임을 인지하고 진입한다.
차별화는 커버리지나 데이터량이 아니라 **판정과 역제안**에서 확보한다.

---

## 4. 서비스 포지션 (중요)

> **이 서비스는 결정해주지 않는다. 현장에 나가기 전에 후보를 걸러준다.**
> **최종 판단은 발품 판 사람의 몫이다.**

이 포지션이 3장의 범위 결정 전체를 지배한다.
"다 안다"고 주장하는 서비스보다 경계를 명확히 긋는 서비스가 신뢰를 얻는다.

---

## 5. 범위

### 5.1 포함

- 주소 + 업종 + 층수 3개 입력만으로 동작
- 4개 축(수요·경쟁·활력·궁합) 기반 적합도 판정
- 층수 × 업종 궁합 보정 및 미스매치 경고
- 4단계 등급: 상 / 중상 / 중하 / 하
- 판정 근거 제시 (긍정·부정·경고 요인 구분)
- 위험 패턴 감지 (함정 상권, 침몰 상권, 포화, 블루오션)
- 대안 업종 1안·2안 추천 + 근거
- 분석 정밀도 명시 (상권 단위 / 행정동 단위 / 분석 불가)
- 커버리지: **서울 단독 런칭** (2026-08-07 변경. 원안은 서울+경기 동시)

**커버리지 변경 사유:** 검증 결과 경기도는 4축 중 실질 1.5축만 채워진다(9.2).
생존율·평균영업기간·매출 분해·배후인구를 확보할 수 없어 활력축과 궁합축을 만들 수 없다.
반쪽짜리 판정으로 첫인상을 소모하는 것보다, **서울에서 판정 품질을 완성하고 검증한 뒤 확장**한다.
어댑터 층(10.1)은 서울 단독 시점에도 그대로 유지해 확장 비용을 미리 낮춰 둔다.

### 5.2 명시적 제외 — 그리고 그 이유

| 제외 항목 | 이유 |
|---|---|
| **월 순익 역산 / 손익분기 계산** | 임대료 오차 하나로 숫자가 통째로 뒤집힌다. **틀린 순익은 없는 순익보다 나쁘다.** 사용자는 정밀해 보인다는 이유만으로 믿어버린다. |
| **임대료·인건비·운영비용 일체** | 현장에서 사람이 확인하고 판단할 영역. |
| **접근성·가시성** (코너 여부, 대로변, 간판 시야, 주차) | 매출을 크게 가르지만 공공데이터에 없고, 물건지 단위 정보다. **눈으로 봐야 하는 영역.** 단 **층수는 예외로 포함**한다 — 6.1 참조 |
| **% 단위 성공 확률** | 창업 성공/실패 라벨 데이터가 존재하지 않는다. 자체 점수에 % 기호를 붙이는 것은 근거 없는 정밀도이며 남의 창업 자금이 걸린 판단에서 위험하다. |
| **자동 지원·중개·계약 연결** | 범위 밖. |

**제외 항목의 공통 원칙:** 현장에서 사람이 보고 판단해야 하는 것은 서비스가 대신하지 않는다.

### 5.3 향후 확장 후보 (1단계 제외)

- **경기 확장 (1순위)** — 상권 경계 폴리곤과 추정매출은 이미 확보 가능(9.2).
  부족한 활력축·궁합축을 어떻게 대체하거나 축소 판정할지가 확장 시 설계 과제
- 부산·대구 등 광역시 확장 (어댑터 추가만으로 가능하도록 설계)
- 사용자 입력 기반 정밀 보정 (임대료 직접 입력 등)
- 프랜차이즈 가맹 희망자 특화 모드
- 기존 자영업자용 상권 모니터링·알림

## 6. 입력과 출력

### 6.1 입력

| 항목 | 형식 | 처리 |
|---|---|---|
| 물건지 주소 | 자유 텍스트 (도로명/지번) | 카카오 지오코딩 → 좌표 → 상권 매칭 |
| 오픈 업종 | 자유 텍스트 | AI가 표준 업종코드로 매핑 (실패 시 목록 선택 폴백) |
| **층수** | 5지선다 드롭다운 | 층수 보정 계수 적용 + 대안 추천 필터 (7.5) |

층수 선택지: **지하 / 1층 / 2층 / 3층 이상 / 단독건물**

**입력은 이 셋으로 고정한다.** 항목이 늘면 이탈률이 오르고,
추가로 물어야 할 것들은 대부분 5.2에서 제외한 영역이다.

**층수를 예외로 포함하는 이유:** 접근성·가시성과 달리 층수는
(1) 사용자가 이미 알고 있는 **객관적 사실**이라 주관이 섞이지 않고,
(2) 드롭다운 하나라 입력 부담이 사실상 없으며,
(3) 업종별로 매출을 결정적으로 가른다.
현장에 가봐야 아는 정보가 아니므로 5.2의 제외 원칙에 저촉되지 않는다.

## 7. 판정 엔진

### 7.1 4개 축

**① 수요 — 이 자리에 사람이 얼마나 있나**
- 지표: 배후세대(거주인구/가구수), 직장인구, 유동인구
- 핵심: **업종마다 중요한 인구가 다르다.** 카페는 유동인구, 세탁편의점은 배후세대,
  국밥집은 직장인구. 이를 뭉뚱그리면 서비스가 무의미해진다. → 7.4 업종 그룹 가중치

**② 경쟁 — 그 파이를 몇이 나누나**
- 지표: 동일업종 점포수, **점포당 추정매출**, 배후세대 대비 점포밀도, 프랜차이즈 비중
- `점포당 추정매출 = 상권 내 해당 업종 추정매출 총액 ÷ 해당 업종 점포수`
- 이 파생 지표를 **전면에 세운다.** 기존 서비스는 상권 총매출만 보여주는데,
  창업자가 궁금한 것은 "동네가 얼마 버나"가 아니라 "내가 얼마 버나"다.

**③ 활력 — 뜨는 곳인가 지는 곳인가**
- 지표: 분기별 매출 증감 추세, 개업률, 폐업률, 점포수 증감, 평균 영업기간

**④ 궁합 — 상권 성격과 업종이 맞나**
- 지표: 요일별·시간대별 매출 구성, 연령·성별 소비 구성
- 이를 업종 특성과 대조한다. 오피스 상권에 주말 장사 업종을 넣으면 안 되는 이유.

### 7.2 등급 산출

```
4축 점수 → 업종 그룹 가중치 적용 → 가중합
       → 동일 업종 상권 풀 내 백분위
       → 4단계 등급
```

**등급은 반드시 「동일 업종 안에서」 매긴다.**
절대 점수로 매기면 마진 구조가 좋은 업종은 어디를 찍어도 상이 나오고,
박한 업종은 명당을 찍어도 하가 나온다. 카페의 상과 세탁편의점의 상은 다른 자다.

| 등급 | 의미 |
|---|---|
| 상 | 적극 추천 |
| 중상 | 해볼 만함, 단 조건부 |
| 중하 | 권하지 않음, 하려면 대비 필요 |
| 하 | 말립니다 |

**3단계가 아니라 4단계인 이유:** 상권분석은 본질적으로 회색지대가 대다수다.
3단계면 약 7할이 "중"으로 떨어지는데 **"중"은 정보량이 0이고 사용자 행동을 바꾸지 못한다.**
애매하더라도 어느 쪽으로 애매한지는 말해야 한다.
4단계는 판정 엔진이 가운데로 숨지 못하게 하는 장치이기도 하다.

### 7.3 패턴 감지 (점수와 독립된 별도 레이어)

조합으로만 드러나는 신호를 잡아낸다. 점수 평균에 묻히면 안 되는 정보다.

| 패턴 | 감지 조건 | 의미 |
|---|---|---|
| **함정 상권** | 유동인구 상위 + 점포당매출 하위 | 통행량이 소비로 이어지지 않음 |
| **침몰 상권** | 매출 하락 + 폐업률 상승 + 점포수 증가 | 최악 조합. 무조건 경고 |
| **포화** | 점포밀도 상위 5% | 신규 진입 여지 없음 |
| **블루오션** | 배후 충분 + 경쟁 하위 | **대안 업종 추천의 핵심 신호** |

블루오션 패턴은 8장의 대안 업종 추천 엔진으로 그대로 연결된다.
별도 로직이 아니라 **같은 계산의 다른 출구**다.

### 7.4 업종 그룹 가중치 — 이 서비스의 영업비밀

100개 업종 × 4축 가중치를 개별 설정하는 것은 비현실적이다.
**업종을 성격별로 6~8개 그룹으로 묶고 그룹 단위로 가중치를 정한다.**

| 그룹 (안) | 예시 업종 | 가중 특성 | 층수 프로필 |
|---|---|---|---|
| 유동의존형 | 카페, 편의점, 분식 | 유동인구 가중 高 | 1층 필수급 |
| 배후의존형 | 세탁편의점, 미용실, 학원 | 배후세대 가중 高 | 2~3층 허용 |
| 직장의존형 | 백반, 국밥, 호프 | 직장인구 가중 高 | 1~2층 |
| 목적방문형 | 전문식당, 공방 | 인구 가중 低 | 층수 영향 小 |

위 4개는 예시이며, 최종 그룹 수는 6~8개 범위에서 확정한다.
**전체 업종을 빠짐없이 어느 한 그룹에 배정하는 것**, **그룹별 4축 가중치 값 확정**,
**그룹별 층수 계수(7.5) 확정**은 모두 구현 일정의 독립 항목으로 잡는다 (13장 5번 리스크).

### 7.5 층수 보정

**층수는 단독으로 좋고 나쁨이 없다. 업종과의 조합에서만 의미를 갖는다.**

```
카페 · 음식점 · 편의점    1층이 아니면 치명적
학원 · 미용실 · 사무형     2~3층 정상 영업
PC방 · 당구장 · 노래방     지하·상층이 오히려 표준
```

따라서 층수는 7.4의 업종 그룹 구조에 얹는다.
**그룹 × 층수(5구간)의 보정 계수 테이블**을 정의하고, 4축 가중합에 곱한다.

**이중 처리:**

| 처리 | 내용 |
|---|---|
| 등급 반영 | 보정 계수를 가중합에 적용 → 등급 자체가 바뀐다 |
| 별도 경고 | 심각한 미스매치(1층 필수급 업종을 2층 이상에)는 경고를 따로 띄운다 |

경고를 따로 두는 이유: 등급 하락에만 반영하면 **왜 떨어졌는지가 사용자에게 보이지 않는다.**

**⚠ 근거의 성격을 명시한다.**
공공데이터에는 **층별 매출 데이터가 존재하지 않는다.**
따라서 층수 보정 계수는 데이터 산출값이 아니라 **도메인 전문가의 휴리스틱**이다.
다른 지표와 근거의 성격이 다르므로 문서·코드·(필요 시) 화면에 이를 구분해 표기한다.

**이 분류표와 가중치가 서비스의 핵심 자산이다.**
데이터는 누구나 무료로 받지만 이 표는 현장 17년을 안 해본 사람은 만들 수 없다.
**작성 주체는 신동환(도메인 전문가)이며, 코드가 아니라 데이터 파일로 관리한다**
(튜닝 시 재배포 없이 교체 가능하도록).

## 8. 대안 업종 추천

### 8.1 계산

사용자가 물은 업종만 채점하지 않고, **해당 상권에서 채점 가능한 모든 업종**
(서울은 100개 생활밀접업종, 경기는 해당 지역 제공 업종 전체)을
**동일 엔진으로 채점**한 뒤 상위를 뽑는다.
추가 데이터도 추가 로직도 필요 없다 — 이미 만든 엔진을 한 번 더 돌리는 것뿐이다.

### 8.2 필수 필터 — 한 겹

**~~필터 ① 「열 수 있는 업종」~~ — 2026-08-08 폐기 (신동환 결정)**

초안은 자격증·고액자본이 필요한 업종(병원·약국·학원 등)을 사전 제외하려 했다.
**폐기한다. 업종 제한을 두지 않는다.**

이유: 이 기능은 **그 자리에 무엇이 맞는가**를 답하는 것이지 **묻는 사람이 그것을
열 수 있는가**를 판단하는 것이 아니다. 자격 요건은 사용자가 이미 아는 정보이고,
의사도 예비창업자다. 또한 제외 목록을 만들기 시작하면 학원·부동산중개업·자동차수리처럼
자격이나 자본이 걸리는 업종이 줄줄이 따라와 기준선이 자의적이 된다.

「자격 필요」 같은 중립적 태그도 붙이지 않는다 — 추천은 점수순 그대로 노출한다.

실측(2026-08-08): 필터 없이 서울 전역 21,188 조합 중 의원·치과의원·한의원이
상위 2개에 오르는 경우 2,043건(9.6%). 이는 **결함이 아니라 의도된 출력**이다.

**필터 ② 「그 층에서 되는 업종」** — 유일한 필터로 남는다

입력받은 층수의 보정 계수(7.5)를 대안 후보 채점에도 동일하게 적용한다.
**2층 물건에 세탁편의점을 추천하면 그것은 헛다리다.**

이 필터는 역제안 기능의 실용성을 결정한다.
층수 입력을 추가한 가장 큰 실익이 여기에 있다.

### 8.3 근거 서술 방식

**"이 업종이 좋습니다"가 아니라 "당신이 물은 업종보다 왜 나은가"로 대비하여 서술한다.**
대비가 있어야 설득이 된다.

## 10. 시스템 아키텍처

**A안 확정: 정적 사전연산 + 룰 판정 + 얇은 AI 프록시**

```
[분기 1회 · GitHub Actions]
  공공데이터 수집 ──▶ 서울/경기 어댑터로 정규화
                        ↓
                  상권 단위 집계 · 업종별 백분위 사전계산
                        ↓
                  지역별 분할 JSON 커밋 (GitHub Pages)

[사용자 요청 · 브라우저]
  주소 ──▶ 카카오 지오코딩 ──▶ 좌표 ──▶ 상권 매칭
  업종 자유입력 ──▶ [AI] 표준 업종코드 매핑
                        ↓
              룰 엔진: 4축 채점 + 패턴 감지
                        ↓
         ┌──────────────┴──────────────┐
    등급 + 근거                 전체 업종 재채점
                                       ↓
                                 1안 · 2안 추천
                        ↓
          [AI] 해설 문장 생성 (Cloudflare Workers 프록시)
                        ↓
                    결과 화면
```

**선정 이유:** 이 프로젝트의 리스크는 인프라가 아니라 **"판정이 쓸모 있느냐"** 하나다.
인프라에는 비용·시간을 쓰지 않고 판정 품질에 집중한다.
비용 0원이며 기존 프로젝트(뉴스앱 등)의 GitHub Actions 패턴을 재사용한다.

### 10.1 어댑터 층 (핵심 설계 원칙)

서울과 경기는 데이터 스키마가 완전히 다르다. **판정 엔진은 이를 알아서는 안 된다.**

```
서울 원본 ──┐
            ├──▶ [어댑터] ──▶ 공통 지표 형식 ──▶ [판정 엔진]
경기 원본 ──┘
```

- 부산·대구 확장 시 **어댑터만 추가**하고 엔진은 한 줄도 수정하지 않는다.
- 공통 지표 형식은 어댑터와 엔진 사이의 유일한 계약이며, 변경 시 양쪽 모두 검토한다.

### 10.2 AI의 역할 — 두 곳으로 한정

| 위치 | 역할 | 폴백 |
|---|---|---|
| **입구** | 자유 입력 업종 → 표준 업종코드 매핑 | 사용자가 목록에서 직접 선택 |
| **출구** | 판정 결과 → 자연어 해설 생성 | 룰 기반 템플릿 문장 |

**판정 자체는 절대 AI에 맡기지 않는다.** 이유:

1. 남의 창업 자금이 걸린 판단이다. LLM은 환각을 일으키고 근거를 대지 못한다.
2. 근거가 한 줄씩 추적되어야 하고, 도메인 전문가가 직접 튜닝할 수 있어야 한다.
3. **LLM에 맡기는 순간 누구나 만들 수 있는 것이 된다.**
   차별점은 룰로 표현된 도메인 지식이며, 그래야 자산이 되고 복제되지 않는다.

- 모델: OpenRouter 경유 (기존 칼로리앱·관상앱과 동일 스택). 무료 모델 우선.
- API 키 은닉을 위해 Cloudflare Workers 프록시 1개만 둔다. 정적 사이트 구조는 유지.
- **AI가 완전히 죽어도 판정은 정상 출력된다.** 문장이 딱딱해질 뿐이다.

### 10.3 분석 정밀도 표기 (제품 정직성)

서울 골목상권 경계는 서울 전역을 덮지 않는다. 상권 미지정 지역 주소 입력이 실제로 빈발한다.
이때 조용히 인근 상권 데이터를 갖다 쓰는 것은 거짓말이다.

| 표기 | 조건 | 처리 |
|---|---|---|
| 🟢 상권 단위 분석 | 주소가 지정 상권 내 | 전체 지표 사용 |
| 🟡 행정동 단위 분석 | 상권 밖 | 행정동 데이터 사용 + 해상도 낮음 명시 |
| 🔴 분석 불가 | 데이터 미제공 지역 | 판정 제공하지 않음 |

**"모른다"고 말할 수 있어야 신뢰를 얻는다.** UX 장식이 아니라 설계 요구사항이다.

## 11. 에러 처리

| 상황 | 처리 |
|---|---|
| 주소 지오코딩 실패 | 재입력 유도. 도로명/지번 예시 제시 |
| 좌표가 서울·경기 밖 | "현재 서울·경기만 지원" 명시. 확장 예정 안내 |
| 상권 매칭 실패 | 행정동 단위 폴백 (🟡 표기) |
| 행정동 데이터도 없음 | 🔴 분석 불가. 판정을 만들어내지 않는다 |
| 업종 AI 매핑 실패/모호 | 후보 목록 제시하여 사용자가 선택 |
| 매핑된 업종의 상권 데이터 없음 | 해당 업종 판정 생략, 대안 업종 추천은 정상 제공 |
| AI 해설 생성 실패 | 템플릿 문장으로 대체. 사용자에게 별도 오류 노출 안 함 |
| 데이터 JSON fetch 실패 | 재시도 후 오류 안내 |

**원칙: 어떤 실패에서도 없는 데이터를 지어내지 않는다.**

## 12. 테스트 전략

- **어댑터**: 서울·경기 원본 샘플 → 공통 지표 형식 변환 결과 검증
- **판정 엔진**: 지표 입력 → 점수·등급 출력의 결정론적 검증.
  경계값(등급 경계 백분위) 케이스 필수
- **패턴 감지**: 4개 패턴 각각의 발동/미발동 케이스
- **층수 보정**: 동일 주소·동일 업종에 층수만 바꿔 넣었을 때
  등급과 경고가 기대대로 변하는지 (5구간 전체)
- **대안 추천**: 필터 ②가 2층 물건에 1층 필수급 업종을 추천하지 않는지
  (필터 ①은 8.2에서 폐기 — 업종 제한 없음이 정상 동작이다)
- **폴백 경로**: AI 양쪽(입구·출구) 실패 시 서비스가 정상 동작하는지
- **정밀도 표기**: 상권 내/밖/미지원 주소 각각에 대해 올바른 표기가 나오는지
- **검증 세트**: 신동환이 실제로 아는 상권 10~20곳을 골라
  판정 결과가 현장 감각과 일치하는지 대조한다. **이 대조가 최종 품질 게이트다.**
